ONE-TIME SETUP

1. Create a public repo named exactly Journal-Writing.
2. Upload everything above, keeping the folder structure.
3. Repo > Settings > Pages > Source: "Deploy from a branch", branch main, folder / (root). Save and wait about a minute for the first build.
4. Create the publishing key (see Tokens), then open each editor, click the gear, paste the token, Save. Now you can write and publish.


TOKENS (READ THIS)

A GitHub fine-grained token only answers "may you write to this repo?" — it does not pick a folder. The folder is decided by each page's hard-coded DATA_DIR, so an editor can only ever write to its own client's data folder. That is deterministic and automatic.

The caveat: a fine-grained token grants write to the whole repo, not a single folder, so the separation is enforced by the code, not by GitHub. Choose based on who publishes.

- You publish for all clients (the intended setup): one token, repo access = Only select repositories > Journal-Writing, Permissions > Contents: Read and write. Paste it into each editor. Zero risk.
- Each client self-publishes and they trust each other: give each their own token, all scoped to Journal-Writing. Separate tokens just let you revoke one without the others.
- Clients who must be cryptographically walled off from each other: don't merge — use separate repos, because a repo is the only level a token isolates at.

To create a token: GitHub > Settings > Developer settings > Personal access tokens > Fine-grained tokens > Generate new token. Set Resource owner to the account that owns the repo, Repository access to Only select repositories > Journal-Writing, and Permissions > Repository permissions > Contents: Read and write. Copy the token (it starts with github_pat_). If it ever leaks, revoke and reissue immediately.

SECURITY: never paste a token into a chat, email, commit, or any file. It lives only in the editor's browser localStorage and is never written into a deployed file.


HOW DATA IS STORED

<Client>-Journal/data/index.json is that client's list of stories (id, title, date, thumbnail). <Client>-Journal/data/posts/<id>.json is one complete story (text, layout, embedded photos). The editor commits these via the GitHub API on Publish. Photos are embedded as compressed data URLs so each story file is self-contained; decorative page backgrounds are the one exception (shared files in assets/backgrounds/, referenced by a short key like bg14).

THEMES

Dhanashri is soft lavender pastel, Pratiksha is warm cream pastel, and Siddhesh is rose pink. A client's palette is chosen by the data-client attribute on its pages (data-client="dhanashri", "pratiksha" or "siddhesh"), which selects the matching block in assets/css/style.css. To retune a colour, edit only that client's block; the others are unaffected.


FEATURES (SAME FOR ALL THREE CLIENTS)

- Photos, Plain look: keeps PNG transparency, so a cut-out image (for example an aeroplane with no background) shows only its subject, with no box and no black fill. Uploads with transparency are now saved as PNG; opaque photos stay small as JPEG.
- Photos, Shadow: an independent toggle that works on any look (frame, border or a plain cutout) and turns fully off when unchecked.
- Photos, Border: its colour and width are adjustable (the default stays the original thin white border).
- Photos, Frame: pick any frame colour; white gives the classic photo-card look (this replaces the old separate Card option).
- Captions: their own font, size and colour controls.
- Text, Bold / Italic / Underline / Strikethrough, and bulleted and numbered lists: all work on a selection inside a box — select a word or two and only those change; with nothing selected they style the whole box.
- The editor is a fixed ribbon at the top: document actions, then Insert / Edit / Arrange / Pages, then a contextual formatting row that swaps for whatever is selected. That row keeps its height, so the canvas never jumps.
- Text, Font / Size / Colour: these work on a selection as well as on the whole box. Highlight a word or a line and change the font, nudge the size, or pick a colour, and only that run changes. With nothing highlighted the control styles the whole box as before.
- Text boxes have two modes. One click on an unselected box selects it and drags it from anywhere. A double-click starts typing, and while typing the box is held still so it cannot be nudged. To move it again, click the empty part of the box (not the words): that leaves typing and starts the move in the same gesture. Clicking the words moves the caret as normal, and Escape also leaves typing. On a phone, tap an already-selected box to start typing.
- Everything resizes from all eight corners and walls. A text box's height is a minimum, so text can grow past it and is never clipped; the ribbon's Fit button shrinks the box back around its text.
- Items are no longer clipped at the page edge while editing, so a box slid off the side stays visible. The published reader still clips at the page edge, as printing does in Word.
- Dragging snaps to the page centre and to other items' edges, with guide lines; hold Alt to place freely. Arrow keys nudge (Shift for 10px), Ctrl+D duplicates, Delete removes, Escape backs out.
- Videos: added by link, not uploaded. See VIDEOS below.
- Plus around forty fonts, alignment, line spacing, text-box fill, rotation, crop, stickers, upload-your-own image stickers, washi tape, doodles, layering, multi-page stories, 28 per-page backgrounds, cover picker, autosave, drafts, and PDF export.


VIDEOS

Click "Video" in the editor's Insert group. It asks for two things: a link to the clip, and a thumbnail image you choose. Only the thumbnail is saved into the story, so the story file stays small however long the video is, and the clip streams from wherever it is hosted.

WHERE TO HOST

The link must be a DIRECT FILE -- an .mp4 or .webm served over https. Cloudinary is the easy way to get one:

1. Make a free Cloudinary account.
2. Media Library > Upload > pick your clip.
3. When it finishes, copy its delivery URL. It looks like
   https://res.cloudinary.com/your-cloud/video/upload/v1699.../clip.mp4
4. Paste that into the editor.

Any other host works too, as long as the link ends at the file itself rather than at a web page about the file.

YOUTUBE AND VIMEO ARE NOT ACCEPTED, ON PURPOSE. Their embeds are iframes and drag their own branding, channel name, title, and like and share buttons onto your page. None of that can be turned off (the old modestbranding switch is deprecated and does nothing, and hiding it with CSS breaks their terms), a Shorts embed is the busiest of the lot, and an iframe cannot go into the PDF at all. A direct file plays in the browser's own player: your clip, plain controls, nothing else. If you paste a YouTube link the editor tells you so rather than failing quietly.

Cloudinary's free tier is 25 credits a month and video is the expensive thing to serve. A handful of clips with light traffic is comfortably fine; if you ever go over, delivery is suspended until the month resets.

HOW IT BEHAVES

The page shows your thumbnail with a play badge on it and loads nothing else. Click it and the real player appears, with the usual play, volume, mute, scrub and fullscreen controls. Several clips can sit on one page: starting one puts the others back to their thumbnails, so two can never play over each other.

A video takes the same looks as a photo. Plain is the clip on its own; Card puts it on a white photo-card with the caption underneath, and you can set the card colour, the corner rounding, the shadow, and the caption's font, size and colour -- so a clip and a photo next to each other match. Double-click the caption to type in it, exactly as with a photo.

The PDF export keeps the thumbnail and the play badge, so a printed page still reads as a video rather than as a photo. This is why the thumbnail is compulsory and why the editor will not let you save a video without one.

WORTH KNOWING

A video is a link, so the story depends on the file staying reachable. Delete it from Cloudinary, or rename it, and the thumbnail remains but the player will not load.

The link is not private. Anyone can read it out of the story JSON, so treat a video the same way you treat anything else you publish to the journal.


JOURNAL COVERS ON THE MAIN PAGE

Each book on the main page shows its journal's own cover.jpg, for example Dhanashri-Journal/cover.jpg. To change it, replace that file with your image under the same name and upload it. Use a landscape 4:3 image, about 800x600; it is cropped to 4:3 from the centre. Browsers may show the old picture for a few minutes after uploading; Ctrl+Shift+R shows the new one at once. The story count and newest date under each book still come from that journal's published stories.


PAGE BACKGROUNDS

In the editor click "Background" to choose a per-page background: grid, dots or plain paper, or one of the decorative images, grouped by mood. A page saves only the background's name, so story files stay small. The images load from the shared assets/backgrounds/ folder, referenced one level up as ../assets/backgrounds/ since each client's pages sit in their own folder.


ADDING MORE BACKGROUNDS

Because assets/ is shared, a new background appears for all three clients at once.

1. Prepare the image. Portrait, about 1100x1447 (the 760x1000 page shape), because the engine stretches a background to fill the page and any other shape looks squashed. JPG or PNG, and keep it small: readers download it in full.

2. Name it the way it should appear in the picker, for example "Soft Pink Glow.jpg", and put it in its group's folder inside assets/backgrounds/. For a new group, make a new folder; its leading number sets the order in the picker and is hidden, so "16 Autumn Days" shows as "Autumn Days". An image placed directly in assets/backgrounds/ appears under "More". Names must be unique across all folders.

3. Double-click assets/update-backgrounds.bat. It rebuilds js/bg-list.js and js/bg-thumbs.js and lists what is new, what was removed and anything worth checking. The first time, Windows may ask you to confirm running it.

4. Upload the changed backgrounds and js folders to GitHub. If the editor still shows the old list, refresh it with Ctrl+Shift+R.

Never edit js/bg-list.js or js/bg-thumbs.js by hand; the .bat overwrites them.

A background's file name is its identity, because stories store it. Moving an image to another group folder is safe, but renaming or deleting one that a published story uses turns those pages into grid paper. The .bat lists removed names, so this never happens silently.


ADDING FEATURES LATER (THE POINT OF MERGING)

Edit the function in assets/js/core.js (and, if it has an editor control, the matching handler, which is identical in all three admin.html files). The change reaches every client at once. One rule: a bug in the shared core hits all journals, so test before publishing.


ADDING A 4TH CLIENT LATER

Copy any client folder (for example Siddhesh-Journal) to NewName-Journal, update the four window.JOURNAL_CLIENT values and the data-client attribute on its three pages, add a matching block for data-client="newname" in assets/css/style.css, and start its data/index.json as an empty list [].
